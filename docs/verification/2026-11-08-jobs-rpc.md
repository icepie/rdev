# Background job RPC while foreground is busy

rdev extensions `get_jobs`, `get_job`, and `cancel_job` expose the existing
thread-local task manager without acquiring a model turn. They are advertised
separately from prompt slash commands, with source=rdev.

`TestJobsRPCDuringForegroundTurn` exercises literal WebSocket frames and checks:

- task list and bounded shell output can be read with foreground admission busy;
- missing threads, missing jobId, and another manager's job ID return errors;
- cancellation acknowledgement precedes worker exit; the worker is held alive
  so a false completed status is observable;
- cancel all is local to the selected thread;
- foreground running state and conversation history remain unchanged;
- a second authenticated socket receives only its own correlated response.

The test uses real background workers and WebSocket connections, with no model
provider. Foreground busy state is set directly, so it verifies admission/history
isolation rather than the quality or latency of a real upstream stream.

Race-enabled targeted tests pass. No web UI change is included.
