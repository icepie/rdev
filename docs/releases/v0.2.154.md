# v0.2.154

Termux/Android 兼容性修复。

## 二进制格式

- Android 的 Go 与 Rust 客户端不再使用 UPX 压缩。UPX 会把 ELF 改写为自带解压存根的形式并删除 `PT_INTERP`（`/system/bin/linker64`），Android 10+ 因 W^X 限制无法执行这种二进制，表现为 `cannot execute: required file not found` 或启动即崩溃。
- 现在发布的是普通 PIE 可执行文件；CI 会在打包后检查 `readelf -l` 仍包含 `program interpreter`，缺失即失败。
- 体积增加：`rdev-client-android-arm64` 由约 6 MB 变为约 18 MB，Rust Android 归档同样变大。

## Shell 与安装脚本

- Go 客户端在 `SHELL` 未设置时按 `$PREFIX/bin/bash` → `$PREFIX/bin/sh` → `/system/bin/sh` 回退，修复 Termux:Boot、`nohup` 等无登录环境下的 shell 启动失败。
- Rust 客户端使用相同的回退顺序。
- `run.sh` 通过 `PREFIX` 含 `com.termux` 识别 Termux，不再依赖可能缺失的 `uname -o`；识别为 `android` 后下载 bionic 资产而不是 linux 资产。

## 验证

- 本机使用 Android NDK 27 构建 `GOOS=android GOARCH=arm64` 客户端，确认产物为带 `/system/bin/linker64` 的 PIE；对同一文件执行 UPX 后确认 `PT_INTERP` 丢失，作为本次修复的证据。
- 新增 `ptyutil` shell 回退测试、Rust `termux_shell` 测试、安装脚本 Termux 检测测试。
- Go、Rust 与脚本测试通过；Web 与 Go 全量测试不受影响。

## 升级

- 旧版 Android 资产是 UPX 压缩的，请重新运行安装脚本获取本版本。
- 服务端升级会短暂断开连接，客户端自动重连。
