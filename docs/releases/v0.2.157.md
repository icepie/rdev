# v0.2.157

队列背压、DXGI 抓屏恢复、GPU 代理流式转发与发布签名。

## 稳定性

- 设备侧共享连接不再被单个慢消费者拖住：文件中继、GPU 子流、会话输入各自有有界队列与写协程。写超时或队列溢出会关闭该连接/子流/会话并记录原因，不再静默丢字节。
- 端口转发的写队列满改为关闭该转发；旧的「等 30 秒后丢一帧继续」会让字节流看似正常但内容截断。
- Web Terminal 正常结束时先排空 stdout/stderr 再发 `exit`；取消结束立即 `exit -1`。关闭输出通道的另一条清理路径不再导致退出帧丢失。

## Windows 桌面

- DXGI 抓屏遇到 `Map` 返回 S_OK 但无数据（或行距为 0）时不再以 `failed: S_OK` 结束会话：先沿用上一帧约 3 秒，再重建 device/duplication/staging 重试一次；仍未恢复则自动切换到覆盖同一区域的 GDI 监视器源继续出画。
- `DEVICE_REMOVED` / `DEVICE_RESET` / `ACCESS_LOST` 直接走重建，不再对已失效设备反复重试。
- `Capture` 与 `Close` 串行化，避免 teardown 在帧映射期间释放句柄。

## GPU 桌面代理

- `/gpu-desktop/<device>/` 的 HTTP 代理改为流式：解析响应头后直接回传正文，只有需要改写 URL 的 HTML/JS 才缓冲（上限 8 MiB，超出返回 502）。
- 请求体限制 32 MiB 并带读取截止时间，超限返回 413。
- 上游在 `Content-Length` 之前断开时中止连接，截断正文不再被当作完整响应。

## Web

- 独立桌面页复用 `attachDesktopMediaSource`：首包早于 `sourceopen`、重连后的旧 MediaSource 事件、卸载清理都已覆盖。
- 移除未引用的 `@vitejs/plugin-basic-ssl`、`@radix-ui/react-checkbox`、`@radix-ui/react-switch`；`@xterm/addon-image` 归入运行时依赖。

## 协议与客户端

- 新增 `docs/protocol-framing.md`：三层帧格式、边界、按传输方式区分的 ID 规则。
- Go、Rust、Java、Web 四方测试共用 `internal/transport/testdata/framing/` 的同一批字节 fixture。
- Rust 偏移帧编解码去掉中间 `Vec` 与二次拷贝；Java 普通会话帧只保留一份 payload。

## 构建与发布

- Windows/macOS 发布产物在标签构建中强制签名（Authenticode / Developer ID + 公证），凭据与 `nicecode-tools` 共用，签名失败即阻断发布；macOS 产物因此不再 UPX 压缩。详见 `docs/release-signing.md`。
- CI 只构建一次 Web 资源并通过 artifact 复用；新增真实浏览器冒烟（设备发现、终端回显、`exit` 帧、文件下载 SHA-256 比对）。
- 构建参数集中到 `scripts/ci/build-go.sh`；Android APK 流程先跑单测再打包。
- Dockerfile 先按锁文件安装依赖再拷源码，`.dockerignore` 补齐本地产物与子模块（构建上下文 9.15 GB → 77.8 KB）。
