# v0.2.149

## 设备名称与系统识别

- Go/Rust 显示名默认使用 hostname；`--display-name` 优先于 `RDEV_DISPLAY_NAME`，空值或纯空白回退 hostname。Android 支持独立显示名及连接链接参数，默认系统设备名/机型。
- 显示名与稳定设备 ID 分离：修改名称不会改变身份凭据、SSH 用户名、连接 URL 或历史归属；旧客户端回退显示 ID。
- Rust 在 WebSocket/TCP/KCP 注册中统一发送 `clientOS`，禁用桌面功能也保留系统信息；服务端规范化 OS 名并兼容旧桌面元数据。
- 保留线上首页精简：不再显示运行健康和设备身份管理面板，服务端 API 与身份校验不变。

## Agent 安全、诊断与性能

- Windows `grep`/`glob` 将路径和模式作为编码数据传入 PowerShell，不再直接拼接 Shell 命令，支持特殊字符目录与 UTF-8 输出。
- 失败诊断随结果检查点保存，重连、服务重启、会话切换与分屏预览可恢复；仅保留有界错误码、提供方/模型/API、结束原因、请求标识、HTTP 状态和输出进度，不存任意响应正文、密钥、提示词或工具参数。
- 内容过滤仍终止执行，不自动重试，不执行未完成的工具调用；补齐 `peek_thread` 分发。
- Responses 文本/思考流改用 builder；命令输出改为固定容量环形缓冲。本地 48 KiB 缓冲、每次 1 KiB 稳态写入为 0 B/op、0 allocs/op，不代表端到端网络吞吐。

## Go 客户端发布与纯 Go H.264

- 删除 `rdev-client-cgo`、x264 Go 绑定、对应构建矩阵和安装器选项；统一的 `CGO_ENABLED=0` Go 客户端改用 BSD-2-Clause 的 `go.264` 软件编码器提供 H.264，并通过 `github.com/icepie/go.264 v1.14.1-rdev.1` 维护分支补充首帧前 SPS/PPS 读取能力，保留 MJPEG 回退。原生 CUA 与硬件编码仍由 Rust GPU 客户端提供。
- Linux 发布构建使用 `go264_nohwaccel` 标签排除 go.264 的可选动态硬件后端，保持客户端静态可执行；WebCodecs 初始化不再预编码并丢弃中性帧，首个真实画面自然成为 IDR。浏览器按到达顺序提交每个 H.264 access unit，不再使用 JPEG 的 latest-frame 合并逻辑破坏预测链。
- H.264 编码器初始化失败时继续在 ready 阶段协商 MJPEG；运行中编码失败时关闭当前流并标记 `format: "h264"`，桌面页和 Agent 面板自动以 MJPEG 重连，避免无限重试损坏的编码路径。
- 未使用 hi264 替代 libx264：其编码器仅面向 16×16/8×8 平色块测试图和 P_Skip，不支持任意桌面像素与运动估计。
- Windows/POSIX 安装器及精确资产解析回归改为覆盖 `go|rs` 两种客户端。

## 验证与升级

- Go 设备注册、平台回退、PowerShell 搜索、缓冲、提供方诊断及历史恢复定向回归通过；Agent transcript 46 项、TypeScript 检查、前端生产构建及 Go 编译通过。
- Go H.264 回归覆盖 RGBA→I420、编码前 SPS/PPS、首个真实 IDR、AVCC 描述、连续 16 帧及奇数尺寸；生成码流由独立 FFmpeg 解码为完整的 Constrained Baseline I420 帧。Linux amd64 静态客户端及 macOS amd64/arm64、Windows amd64/386 交叉构建通过。托管 Chromium 的 H.264 解码器连已知 x264 对照码流也返回 `EncodingError`，因此浏览器实机播放仍需在带 H.264 支持的 Chrome 上验收。
- Rust 空显示名回退回归及构建、Android DeepLinkConfigTest 通过。真实 Go/Rust 客户端确认默认显示名等于 hostname，稳定 ID 不变。
- Chrome 验证显示名与连接 URL，以及真实提供方连接失败后的诊断显示与刷新恢复。Windows/macOS 和 Android 真机界面未验收。
- 服务端升级会短暂断开连接，客户端自动重连；客户端显示名与系统上报更新需要升级对应客户端。各平台安装包和签名由 tag CI 构建发布，不移动旧版本 tag。
