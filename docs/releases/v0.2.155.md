# v0.2.155

Termux 权限相关补充修复。

## Shell 执行权限

- Go 客户端启动会话时，如果检测到的 shell 存在但不可执行（缺少执行位、被更新删除、Android 路径不对），会依次尝试剩余候选而不是直接失败：`$SHELL` → `$PREFIX/bin/bash` → `$PREFIX/bin/sh` → `/system/bin/sh` → `/bin/bash` → `/bin/sh`。
- 仅对 `EACCES`/`ENOENT`/`ENOEXEC` 做回退，其它错误立即返回，避免掩盖真实故障；回退时会记录实际使用的 shell。
- Rust 客户端同样只接受带执行位的 shell：`$SHELL` 不可执行时继续按 Termux 前缀与系统路径查找，不再把失效的 `$SHELL` 传下去。

## 说明

- `pkg install`、`termux-setup-storage` 这类权限仍由 Termux 自身管理；`/sdcard` 未授权的读写错误需要用户执行 `termux-setup-storage`，客户端不会绕过。
- Android 客户端仍为普通 PIE（见 v0.2.154）；若从旧版本升级，请重新运行安装脚本。

## 验证

- 新增 `ptyutil` 回退单元测试（错误分类、候选去重）与 Rust 可执行位测试，Go/Rust 全量测试通过。
- 安装脚本 Termux 检测与 noexec 回退测试保持通过。
